# T800 庆祝动作手臂重定向修正设计

## 目标

在不修改 EngineAI 默认 PPO、T800 物理限位和 `ee_body_pos` 终止条件的前提下，修正 LAFAN1 `dance1_subject2` 庆祝片段经 GMR 直接重定向到 T800 后的手臂动作范围，使策略能够学习连续的庆祝动作。

当前输入保持不变：

- 源动作：`dance1_subject2.bvh` 的 `[2880, 3180)`，300 帧、30 fps。
- 机器人：EngineAI T800。
- 链路：LAFAN1 BVH → GMR → T800 CSV → Isaac Lab NPZ → EngineAI tracking PPO。
- 训练任务：`Tracking-Flat-T800-Wo-State-Estimation-v0`。

任务 a 的 `t800-oldgmr-walk10-drop2-tilt-w05-free30-pipeline` 训练不得停止。

## 已确认的根因

探针并非因脚踝、根姿态、关节顺序或 CSV→NPZ 转换错误而失败。1000 步诊断中，双脚踝没有触发 `ee_body_pos`，复位由双手腕高度误差触发。

庆祝参考动作中，肩部 yaw 长时间接近 85% 物理限位。默认控制中肩部 yaw 的动作尺度只有 `0.05`，保持这些参考关节角需要约 `±44.5` 的原始动作。环境复位时动作历史清零，而 `action_rate_l2` 权重为 `-0.075`，正确保持参考姿态会产生远高于正向跟踪奖励的首步动作变化惩罚。500 轮策略实际输出仍接近零，手臂回落后手腕高度误差超过 `0.35 m`，形成高频复位。

## 方案选择

采用动作尺度感知的手臂姿态正则，作为现有 GMR IK 的低权重任务：

1. 保留 EngineAI 官方 LAFAN1→T800 位姿匹配表、两阶段 IK、根姿态修正和 85% 关节限位。
2. 使用 Mink `PostureTask`，目标为 EngineAI tracking PPO 的 T800 默认关节姿态，而不是 MuJoCo XML 中全零的 `qpos0`。其中双肩 roll 为 `+0.15/-0.15 rad`，双肘 pitch 为 `-0.25 rad`，其余手臂默认角为零。
3. 只对双臂关节设置正则权重；根、腿、腰和头部权重为零。
4. 权重按控制动作尺度的倒数分配，使动作尺度为 `0.05` 的肩/肘 yaw 比动作尺度为 `0.2` 的 pitch/roll 受到更强约束。
5. 正则同时加入 GMR 的两个 IK 阶段，让求解器在保持人体手臂末端目标的同时，优先选择更容易被默认控制器执行的关节组合。
6. 新功能通过独立 CLI 参数启用；参数为零时输出必须与当前基线一致，便于回滚和对照。

不采用以下方案：

- 不删除或放宽手腕终止项，因为这会掩盖手臂跟踪失败。
- 不直接裁剪 GMR 输出的肩部 yaw，因为这会在不了解末端位置误差的情况下破坏庆祝语义。
- 第一轮不更改 LAFAN1 肩部目标链接和四元数偏置；若姿态正则无法通过量化门禁，再单独设计肩部链接映射实验。
- 不修改 PPO 动作尺度和奖励，以保持与官方 baseline 的可比性。

## 代码边界

修改范围限定在 `GMR-engineai-work`：

- `scripts/bvh_to_t800_csv.py`
  - 构造动作尺度感知的手臂姿态代价向量。
  - 创建并安装 Mink `PostureTask`。
  - 增加显式 CLI 参数并在日志中输出实际代价。
- `tests/test_bvh_to_t800_csv.py`
  - 测试默认禁用行为。
  - 测试只选择双臂关节。
  - 测试 `0.05` 动作尺度关节的代价高于 `0.2` 关节。
  - 测试姿态目标使用 EngineAI PPO 的 T800 默认手臂角，并保持根状态来自模型 `qpos0`。
  - 测试无效参数被拒绝。

EngineAI RL Lab 的 PPO、环境、终止配置和任务 a 文件均不修改。

## 数据流与候选选择

1. 用原庆祝 BVH 和原参数生成基线 CSV，记录基线哈希及指标。
2. 对少量正则强度执行单变量候选扫描；每次只改变姿态正则强度。
3. 对每个候选计算关节限位、默认动作空间、手腕轨迹和根/腿差异指标。
4. 选择满足全部量化门禁的最小正则强度，避免不必要地削弱庆祝动作。
5. 生成 T800 重定向视频，自检庆祝语义、摔倒、锁死、前倾、悬空和小臂反向。
6. 通过数据门禁后，将选中 CSV 转为 50 fps NPZ，并做重建一致性检查。
7. 使用独立名称运行 256 环境、500 轮、默认 PPO 探针，与旧探针进行相同指标和视频对照。
8. 只有探针门禁通过后，才评估正式 4096 环境、20000 轮训练；任务 a 仍运行且显存不足时等待其自然完成。

## 量化门禁

候选 CSV/NPZ 必须同时满足：

- 双肩 yaw 在 85% 限位边界的贴边帧比例小于 5%。
- 双肩 yaw 映射到默认动作空间后的绝对值 p95 不超过 25。
- 以零动作历史复位时，双臂动作变化惩罚的 p95 不超过 75。
- 所有关节均在 85% 物理限位以内，且不存在 NaN/Inf。
- 相对基线的根姿态和腿部关节 RMS 差异不超过 `0.02 rad`；根位置 RMS 差异不超过 `0.01 m`。
- 双手腕轨迹相对基线的三维偏差 p95 不超过 `0.10 m`。

探针必须同时满足：

- 日志无 `Traceback`、CUDA OOM 和 `RuntimeError`。
- `Episode_Termination/ee_body_pos` 相比旧探针显著下降，不再接近 1.0。
- Mean episode length 明显高于旧探针最后 50 轮均值 `10.84`。
- 单环境视频包含可辨识的连续庆祝语义，且无高频复位、摔倒、锁死、明显前倾、脚部悬空和小臂反向。

如果没有任何候选通过 CSV/NPZ 门禁，则停止在数据阶段，保留全部对照结果，不启动新探针，并重新设计 LAFAN1 肩部链接映射实验。

## 错误处理与可回滚性

- 新 CLI 参数默认为关闭，确保旧命令行为不变。
- 每个候选使用独立输出目录、日志和名称，不覆盖当前庆祝 CSV、NPZ、视频、模型或官方 GMR 配置。
- 任一测试、数据门禁、视频门禁或资源检查失败即停止后续阶段。
- 所有诊断及候选结果记录到 `T800_CONTEXT.md`，便于交接给其他 AI 或成员。

## 验证策略

实现采用测试驱动：先增加失败测试，再写最小实现，并运行完整 `test_bvh_to_t800_csv.py`。随后进行基线兼容性测试、候选数据量化、视频检查、NPZ 重建检查和探针对照。完成声明必须以同一轮新鲜日志、指标和视频为依据。
