# T800 挑衅与庆祝动作训练设计

> **2026-08-21 范围变更：** 用户最新决定只训练庆祝动作。挑衅动作的数据、视频和2轮冒烟结果仅保留为历史资产，不再运行其500轮探针或正式训练。下面涉及“双动作分别训练”的文字是最初设计记录；当前实际执行范围以庆祝动作 `dance1_subject2` 帧 `[2880, 3180)` 为唯一目标。

## 目标

从现有 LAFAN1 动作库中选取两个10秒片段：

- `multipleActions1`：挑衅动作。
- `dance1`：庆祝动作。

两个片段分别从人体 BVH 直接重定向到 T800，完成数据质量检查后，使用 EngineAI `engineai_rl_lab` 的全身动作跟踪任务分别训练两个策略。任务 b 不使用任务 a 的 walk 数据，也不经过 G1 中间机器人。

## 已确认的基础条件

- 本地动作库：`<LOCAL_WORKSPACE>\lafan1_source\lafan1.zip`。
- `multipleActions1_subject1..4.bvh`：每段152.90秒、30 FPS、4587帧。
- `dance1_subject1..3.bvh`：每段131.50秒、30 FPS、3945帧。
- 服务器项目：`<SERVER_USER_DIR>/engineai_rl_lab-main`。
- Python：`<SERVER_USER_DIR>/isaac_env/bin/python`。
- 任务：`Tracking-Flat-T800-Wo-State-Estimation-v0`。
- 官方基础配置：4096环境、20000轮、每2000轮保存。
- 官方 `dance_t800.npz` 已通过16环境×2轮冒烟，只证明环境链路可运行，不是本任务最终数据。

## 动作选择

已为7个候选 BVH 生成2秒全局抽帧和0.5秒局部抽帧预览。最终固定以下两个连续10秒窗口；帧号使用从0开始、结束帧不包含的写法：

| 动作 | 源文件 | 时间范围 | 帧范围（30 FPS） | 选择原因 |
|---|---|---:|---:|---|
| 挑衅 | `multipleActions1_subject4.bvh` | `[108.0, 118.0)` 秒 | `[3240, 3540)` | 连续格斗架势、挥臂与压低重心，挑衅语义最明确；无倒地和物体交互 |
| 庆祝 | `dance1_subject2.bvh` | `[96.0, 106.0)` 秒 | `[2880, 3180)` | 包含两次明显的双臂上举和舞步，庆祝语义清楚；无地面动作和连续高速旋转 |

原始片段各为300帧，转换到50 FPS后各约500帧。后续预览、GMR、CSV、NPZ和训练均以这两个窗口为准，不再处理完整的两分钟源序列。

### 挑衅动作

仅从 `multipleActions1_subject1..4.bvh` 选择。窗口必须满足：

- 动作含义可识别为挑衅或挑战，而不是普通走路、倒地或物体交互。
- 机器人主要保持原地，允许小范围跨步，但不应持续移动出训练区域。
- 起始约1秒为自然准备，中央约8秒为主体，末尾约1秒自然收势。
- 不依赖手指、面部表情或 T800 不具备的自由度表达含义。

### 庆祝动作

仅从 `dance1_subject1..3.bvh` 选择。窗口必须满足：

- 动作含义可识别为庆祝，优先选择双臂上举、挥臂等全身表达。
- 避免连续高速旋转、大幅跳跃、劈叉和地面动作。
- 起始约1秒为自然准备，中央约8秒为主体，末尾约1秒自然收势。

两个窗口均保持原始30 FPS与原始速度，不做时间拉伸或压缩。最终选中的 subject、起止帧和起止秒数写入数据清单。

## 数据链路

```text
LAFAN1 BVH 10秒片段（30 FPS）
  -> 人体直接到 T800 的 GMR
  -> T800 CSV
  -> GMR 人体/T800 对比视频
  -> EngineAI CSV-to-NPZ（50 FPS，约500帧）
  -> Isaac Sim T800 直接回放视频
  -> 单动作 PPO 探针
  -> 单动作正式 PPO
  -> 策略、曲线、视频和总结
```

挑衅与庆祝的数据、日志、tmux和模型目录必须完全分开，不把两段动作拼接到同一个 NPZ，也不训练一个混合策略。

### 自己拍摄动作的扩展分支

本设计当前选用 LAFAN1 BVH，因此跳过 GVHMR。以后若改为自己拍摄的单目视频，则复用此前考核路线，并只替换数据链路的输入端：

此前考核的 `<SERVER_USER_DIR>/GAOTIANHAO-G1-BeyondMimic` 是 G1 工程参考，不作为 T800 正式训练入口。T800 仍使用 `<SERVER_USER_DIR>/engineai_rl_lab-main`；GVHMR 的安装、权重和短视频冒烟需在首次自拍视频任务前单独恢复与验证。完整环境与遗留资产记录见 `T800_CONTEXT.md` 第15节。

## 重定向与数据验收

GMR 使用现有 EngineAI T800 适配工作版，直接将人体骨架映射到 T800。每段动作在训练前必须通过以下检查：

1. 输出长度为10秒，帧序连续，无 NaN、Inf 或四元数突变。
2. 25个关节的名称、顺序和正负方向与 EngineAI T800 模型一致。
3. 所有关节满足 T800 物理硬限位；额外报告接近限位的关节和帧数。
4. 根姿态没有错误的前倾、侧倾、90度偏航或高度漂移。
5. 双脚没有持续悬空、穿地或明显滑动；需要离地的动作必须与人体源动作一致。
6. 肩、肘俯仰、肘偏航和小臂方向与人体表达一致，无反向折叠。
7. 无严重身体自碰撞和高速抖动。
8. 起止姿态均能自然衔接 T800 站立姿态。

若 GMR 视频不合格，问题停留在 BVH 选段或重定向阶段处理，不进入 NPZ 或 PPO。

## 训练组织

当前只对庆祝动作执行以下三个门槛。用户已明确授权在门禁通过后自动进入下一阶段；任务 a 不得被停止，正式4096环境若与任务 a 并行显存不足，则等待任务 a 自然结束后再启动。

每个动作使用独立策略，依次经过三个门槛：

### 1. 数据链路冒烟

- 16环境、2轮。
- 目的：确认 NPZ 能加载、USD能实例化、CUDA正常、模型能够保存。
- 通过条件：2/2轮完成，产物非空，无 Traceback、CUDA error 或 OOM。

### 2. 质量探针

- 256环境、500轮。
- 使用官方 PPO、奖励、随机化和无状态估计任务，不同时修改超参数。
- 训练结束后生成单环境视频。
- 通过条件：末段平均奖励高于初段，平均 episode length 上升，`ee_body_pos` 终止率下降；视频中动作开始具有正确语义且机器人没有立即摔倒或锁死。

### 3. 正式训练

- 4096环境、20000轮，沿用官方默认配置。
- 保存间隔2000轮。
- 计划视频节点：`model_2000`、`model_6000`、`model_10000`、`model_14000`、最终模型。
- 挑衅探针通过后才进入挑衅正式训练；庆祝动作采用相同门槛并使用独立目录。

任务 b 的任何训练均只在用户明确要求时启动。不得停止任务 a 释放显存；启动前先检查 RTX 5090 剩余显存，资源不足则等待。

## 最终验收

每个动作必须满足：

- 单环境视频能连续完成10秒，不摔倒、不冻结。
- 动作能够被肉眼区分为挑衅或庆祝，而不是随机挥臂。
- 躯干稳定，无明显错误前倾和持续摇摆。
- 脚部接触符合源动作，无持续悬空、穿地或严重滑步。
- 关节无硬限位越界，小臂方向正确，无明显自碰撞。
- 训练日志完整，奖励趋势稳定，最终模型与配置文件非空。

## 失败定位顺序

```text
人体源视频不合格
  -> 更换 subject 或10秒窗口

人体源正确、GMR视频错误
  -> 修正人体到T800的根坐标、关节轴或限位映射

GMR正确、Isaac直接回放错误
  -> 检查CSV/NPZ关节顺序、FPS、根姿态和USD

Isaac直接回放正确、PPO探针错误
  -> 检查奖励、终止条件、动作缩放和PPO配置
```

禁止通过完整20000轮训练来试错数据映射问题。
