# UFO 论文阅读总结与答辩准备

论文：**UFO: A General Unsupervised Reinforcement Learning Framework for Humanoid Control**
作者：RoboParty Lab Team
版本：2026-07-14
原文：[UFO.pdf](https://roboparty.github.io/UFO/assets/UFO.pdf)
代码：[Roboparty/UFO](https://github.com/Roboparty/UFO)

> 本文档既用于向学姐汇报，也用于口头问答。正文中的页码均指 PDF 页码。

## 1. 一句话概括

UFO 是一个面向人形机器人**无监督强化学习行为基础模型**的开源框架。它不是只提出一个新算法，而是同时完成了四件事：加速并改进 FB、提出并接入 TeCH、抽象多机器人和多数据集接口、验证抗干扰实机遥操作。

## 2. 论文想解决什么问题

传统人形机器人控制通常为每个任务手工设计奖励，或把问题写成参考动作跟踪。这样虽然能把单个动作训得很准，但有四个主要问题：

1. **训练成本高。** 大规模动作跟踪依赖大量动作、并行环境和 GPU。例如论文引用的 SONIC 使用 128 张 GPU 连续训练 7 天。
2. **行为受数据分布限制。** 跟踪策略主要学习数据里已有的动作，难以覆盖高自由度机器人完整的状态—动作空间。
3. **已有无监督框架不够通用。** BFM-Zero 展示了 FB 的潜力，但原有实现训练慢、显存要求高，而且和特定机器人、数据、算法耦合较深。
4. **实机验证不足。** 特别是受到推、拉、踢以及跌倒后，策略能否恢复并继续遥操作，过去的开源系统缺少充分展示。

UFO 的核心思路是：不为每个下游任务重新设计奖励，而是在预训练阶段先学一个覆盖广、连续、可复用的行为潜空间，再通过潜变量条件控制完成动作跟踪、目标姿态到达、奖励优化或遥操作。

## 3. “无监督”到底是什么意思

这里的“无监督”容易被问到。它并不表示完全不用数据，也不表示训练中没有任何奖励信号。

- 训练会使用**无标签动作数据**和在线交互数据。
- 不需要为“走路、下蹲、起身、抗推”等每个任务分别编写任务奖励。
- 动作示范用于形成行为先验、判别器约束或潜空间锚点。
- 算法仍会产生内在奖励或表示奖励，例如 TeCH 的“朝潜空间目标前进了多少”。
- 为了 sim-to-real，还会加入关节限位、域随机化等辅助约束。

因此，更准确的说法是：**没有下游任务专属奖励的行为预训练**，而不是“无数据、无奖励”。

| 贡献 | 做法 | 结果 |

| UFO-FB 高效训练 | mjlab 轻量仿真、并行环境、分布式 off-policy 训练、扩大 buffer/batch 并调参 | 训练从约三天缩短至数小时，同时优于发布的 BFM-Zero |

## 5. 问题建模

论文把实机人形控制写成 POMDP：`(S, O, A, P, γ)`。

- `S`：完整状态空间。
- `O`：策略实际可观测的信息。
- `A`：动作空间。
- `P`：状态转移。
- `γ`：折扣因子。

论文以 29-DoF G1 为例：

- 动作 `a ∈ R^29`：29 个关节的 PD 目标值，而不是直接输出力矩。
- 特权状态 `s ∈ R^463`：包括根高度、各刚体姿态/朝向、线速度和角速度等，只在训练中使用。
- 单帧可观测状态 `o ∈ R^64`：
  - 相对默认姿态的关节位置 `q - q̄`：29 维；
  - 关节速度：29 维；
  - 根角速度除以 4：3 维；
  - 根坐标系下投影重力：3 维。
- 观测历史：历史本体状态与动作的拼接，用来缓解部分可观测性。
- 除根高度外，状态通常相对当前 heading 和根位置归一化，减少全局位置、朝向对学习的干扰。

这里的关键不是死记 463，而是理解：**critic/训练过程可以看见更多特权信息，部署策略主要依赖本体感知历史。**

## 6. UFO-FB：为什么能更快

### 6.1 FB 的角色

Forward-Backward representation learning 通过结构化潜表示描述长时行为。策略以潜变量 `z` 为条件，能够在同一模型中生成不同技能，并支持技能插值、目标驱动和奖励优化。UFO-FB 是 UFO 对 BFM-Zero 主算法的高效实现，不是论文新提出 FB 本身。

### 6.2 系统层优化

1. **mjlab 轻量仿真后端**：提高单机仿真吞吐。
2. **同步数据并行**：每张 GPU 有独立环境和 replay buffer；每次优化后通过 `torch.distributed` 手工 all-reduce 平均梯度。
3. **off-policy 经验复用**：在线数据进入 replay buffer，可多次用于训练，不像纯 on-policy 方法每轮都丢弃旧经验。
4. **规模扩大**：增加并行环境、buffer 容量和 batch size，提高探索覆盖和优化稳定性。
5. **超参数重新优化**：尤其是潜变量更新频率和分布式训练参数。

### 6.3 训练效率结果

| 方法 | 硬件 | 环境数 | 达到可实机部署性能的时间 | 吞吐 |
|---|---:|---:|---:|---:|
| BFM-Zero | 1×H200 | 1024 | 45 h | 763.6 FPS |
| UFO-FB | 1×H200 | 1024 | 21 h | 993.4 FPS |
| UFO-FB | 8×H200 | 8×1024 | 6 h | 4824.7 FPS |
| UFO-FB | 8×RTX 4090 | 8×512 | 14 h | 1284.0 FPS |

需要注意论文中的几个时间口径：

- 摘要写“从三天缩短到 6–8 小时”，主要对应高端多卡配置。
- 表 1 给出的 8×H200 是 6 小时，8×RTX 4090 是 14 小时。
- 正文又说 4090 大约 12–14 小时。
- 论文还说默认 8×H200 只训练 3–4 小时的策略已经能做较强的实机演示，但这不等于完整收敛时间。

如果被问“到底几小时”，应先问清楚硬件和“可用”还是“完整平台期”，不能只背一个数字。

### 6.4 性能结果

| 方法 | EMD↓ | 跟踪 Joint MAE↓ | Goal MAE↓ | 24 奖励平均回报↑ |
|---|---:|---:|---:|---:|
| BFM-Zero，1×H200 | 0.731 | 0.1510 | 0.139 | 207.3 |
| UFO-FB，1×H200 | 0.668 | 0.1266 | 0.130 | 243.0 |
| UFO-FB，8×H200 | **0.639** | **0.1178** | **0.115** | 240.8 |
| UFO-FB，8×RTX 4090 | 0.693 | 0.1254 | 0.124 | 232.2 |

EMD 衡量生成动作分布与参考动作分布的差异；Joint MAE 衡量关节配置误差。两个指标都是越低越好。

### 6.5 消融实验的结论

- `update-z` 越小，潜条件更新越频繁，跟踪误差通常越低。
- 但更新太频繁会降低时间压缩，使动作不够柔和，并在实机上更容易出现调整步和抖动。
- 论文建议 `update-z = 10–100` 作为精度与稳定性的折中。
- 增加每卡环境数能提升探索效率，但超过约 `1024 env/GPU` 后边际收益明显减小。
- 增加 GPU 数和总 buffer 能明显加快早中期的墙钟收敛，但不是简单的“卡数翻倍、最终精度也翻倍”。

## 7. UFO-TeCH：论文真正的新算法

TeCH 全称是 **Temporal Distance Modeling via Contrastive Representation Learning for Humanoid Whole-Body Control**。它是作者把 TLDR 的时间距离表示思想适配到人形机器人后的算法。

### 7.1 直觉

普通状态表示只关心两个姿态“长得像不像”；TeCH 更关心：**从当前状态经过机器人动力学，需要多少步能到另一个状态。**

如果两个状态时间上可快速互达，它们在潜空间应更近；如果需要很长路径，它们应更远。这样潜空间不仅包含姿态外观，还包含可达性和行为进程。

### 7.2 时间距离表示

从转移 `(s_t, s_{t+1})` 出发，在未来轨迹中采样伪目标 `g_t`，再通过共享编码器得到：

```text
φ_x = φψ(s_t)
φ_y = φψ(s_{t+1})
φ_g = φψ(g_t)
```

编码器损失包含两部分：

```text
L_TE = -L_dist(φ_x, φ_g) + λ L_step(φ_x, φ_y)
```

- `L_dist`：让时间上相距较远的状态在潜空间可区分，学习长时可达关系。
- `L_step`：约束相邻状态保持平滑，避免潜表示突然跳变。

两者共同形成“局部连续、全局能表达时间距离”的潜空间。

### 7.3 目标进度奖励

给定潜目标 `z`，TeCH 奖励为：

```text
r_t = ||z - z̄(s_t)||² - ||z - z̄(s_{t+1})||²
```

若下一状态比当前状态更接近目标，奖励为正；反之为负。这是稠密、带方向性的进度信号，比只在最终到达时给奖励更容易优化。

### 7.4 三类潜目标来源

训练时 `z` 不是只从一种分布采样，而是混合：

1. 随机潜变量：扩大探索范围和技能多样性；
2. 在线样本对应的潜表示：提供当前策略实际可达的目标；
3. 专家轨迹的潜表示：注入人体动作先验并提供稳定锚点。

这三者分别对应**多样性、可达性、动作先验**。

### 7.5 三个 critic 与更新顺序

Actor 同时受三个 Q 函数优化：

- `Q_REP`：来自 TeCH 目标进度奖励；
- `Q_D`：判别器/风格 critic，使机器人行为接近人体动作分布；
- `Q_R`：辅助 critic，承载关节限位和 sim-to-real 等辅助目标。

整体更新顺序是：

```text
环境交互 → replay buffer
→ Discriminator
→ Temporal Encoder
→ Main Critic + Auxiliary Critic
→ Actor
→ Target Network soft update
```

Actor 目标可概括为最大化三个 Q 的加权和。

### 7.6 零样本推理

- **目标姿态到达**：把目标状态编码为 `z_g = φ(s_g)`。
- **轨迹跟踪**：把未来时间窗内多个状态的编码做加权聚合，形成随时间变化的 `z_t`。

TeCH 不是 successor-feature 方法，因此没有 FB 那种统一的 value-based 奖励优化接口。它擅长目标到达和轨迹跟踪，但通常不能直接完成 BFM-Zero/UFO-FB 的任意奖励优化。这是 TeCH 的能力边界，不应说它全面取代 FB。

## 8. TeCH 实验说明了什么

仿真频率为 200 Hz，控制频率为 50 Hz。

- 训练集：重定向到 G1 的 LAFAN1，40 段、总计约 2–3 小时。
- 测试集：100-Style，约 3000–4000 段、总计约 18–19 小时。
- 评估时主要使用关节位置 MAE，并且 UFO/BFM-Zero/SONIC 的完整轨迹对比不做早停。

| 方法 | LAFAN1 Joint MAE↓ | 100-Style Joint MAE↓ |
|---|---:|---:|
| SONIC，完整轨迹 | 0.2916 ± 0.1887 | 0.1522 ± 0.1049 |
| SONIC，只统计终止前 | 0.1081 ± 0.0213 | 0.1355 ± 0.0351 |
| BFM-Zero，完整轨迹 | 0.1510 ± 0.0255 | 0.1674 ± 0.0459 |
| UFO-FB，完整轨迹 | **0.1178 ± 0.0575** | **0.1278 ± 0.0403** |
| UFO-TeCH，完整轨迹 | 0.1272 ± 0.0582 | 0.1385 ± 0.0392 |

SONIC 终止前的短段精度可以很好，但跌倒或遇到地面状态转换后不容易恢复，因此完整轨迹指标恶化。UFO 的优势不只是瞬时跟踪误差，而是通过广泛的无监督探索覆盖异常状态，跌倒后仍能回到可控状态。

TeCH 在目标到达中往往更快，但最终精度会略有下降；跌倒后也比 UFO-FB 更快恢复，不过强调最短时间可达可能使恢复动作不如人类自然。

## 9. 多机器人迁移

UFO 把以下接口从算法中分离：

```text
机器人 MJCF/URDF
→ RobotTrainingSpec（关节、语义、执行器、限位、默认状态）
→ RobotState 动作（root pose + XML/control-joint 顺序的 joint positions）
→ full inference cache + clipped training cache
→ 同一套训练、推理、导出代码
```

新机器人配置必须明确：

- actuated joint/action 顺序；
- action 维度；
- body 语义，例如 root、feet、hands、torso；
- actuator 力矩/速度限制和关节动力学；
- 默认姿态和接触结构；
- 与机器人对应的重定向动作数据。

作者展示了 G1、Booster K1、H1、RP1、RPO、AgiBot X2 等不同形态。重点不是“模型天然零配置支持任何机器人”，而是**更换机器人配置和机器人专属动作数据后，可以复用算法、训练和推理主干**。

## 10. 新技能注入

直接把少量高难动作混入大数据池，再对所有动作统一做 prioritized sampling，会产生问题：高动态动作因为长期难跟踪而一直获得高优先级，训练分布被少数难动作控制，最终使 actor 和 Q 指标发散。

论文的 cartwheel 实验中，朴素合并方案在约 14–28M 环境步出现非有限指标，之前还伴随异常 torso height 和巨大接触力。

UFO 的解决办法是**固定比例的数据集级混合**：

1. 先按固定分类分布选择数据集；
2. 再只在选中的数据集内部做 prioritized sampling。

cartwheel 使用 foundation/cartwheel = `0.95/0.05`。这样新技能获得稳定但受控的曝光，同时不破坏原有行为分布；实验稳定训练到 384M 环境步。

## 11. 实机遥操作链路

```text
Pico VR + 两个脚部 tracker
→ 50 Hz 人体动作捕获
→ GMR 重定向到机器人
→ 表示编码器生成 latent goal
→ UFO policy 推理
→ Unitree SDK2 / CycloneDDS 控制机器人
```

重定向、潜表示推理、策略执行和机器人控制是独立模块，通过 ZeroMQ 通信。编码器和策略既可以运行在机器人端，也可以运行在以太网连接的工作站上。

工程安全措施包括 watchdog、数据包超时检测、命令合法性校验和急停。实机演示覆盖前后行走、跑步、上下肢动作、深蹲、跪地、滚地、快速起身、接箱子和踢箱子，并进行多人的推、拉、踢干扰实验。

## 12. 论文明确承认的局限

1. 与专门的遥操作框架相比，UFO 的跟踪精度和动作质量仍有差距。
2. 行走稳定性不足，尤其是后退和侧向行走。
3. 全局跟踪精度有限。
4. backward mapping network 较大，导致遥操作延迟明显。
5. 预训练只用了 LAFAN1，缺少足够的行走和真实交互动作。
6. 完全无监督训练不能依赖任务专属终止条件，例如 root drift 过大时终止。
7. TeCH 不提供 FB 式的统一奖励优化接口。
8. TeCH 强调时间可达性，快速恢复动作可能不够像人。

这些限制非常重要。汇报时主动说出局限，比只复述宣传性结论更能证明读过论文。

## 13. 与当前 T800 工作的关系

我们正在做的并不是简单把 G1 名字替换成 T800，而是在落实论文第 6.1 节的多机器人适配接口：

- 明确 T800 的 25 个 action/joint/actuator 顺序；
- 配置 root、feet、hands、torso 等 body semantics；
- 导入 T800 MJCF/URDF、执行器参数、PD 参数和物理限位；
- 使用直接重定向到 T800 的 RobotState 数据，而不是把 G1 policy 直接套到 T800；
- 生成 full cache 与近 10 秒训练 cache；
- 先做 CPU 环境和小规模 GPU smoke，再决定是否扩大训练。

当前用于 UFO 第一阶段的是 302 帧、30 FPS 的 direct-T800 CSV。它会按 `root XYZ + root quaternion XYZW + 25 joints` 导入，并严格遵循 T800 XML/control-joint 顺序。这和论文描述的 RobotState 接口一致。

需要区分：UFO 是无监督行为基础模型框架；我们之前在 rl_lab 中做的动作 tracking PPO 是针对指定动作的模仿训练。二者不是同一个训练目标，也不能用同样的轮数直接比较。

## 14. 三分钟口头汇报稿

UFO 是 RoboParty Lab 提出的通用人形机器人无监督强化学习框架。它想解决的是，现有动作跟踪方法需要大量数据和算力，策略又容易受训练动作分布限制；而已有 BFM-Zero 虽然证明了 FB 无监督行为模型可行，但训练慢、显存要求高，且机器人和算法扩展性不足。

论文有四项核心贡献。第一，UFO-FB 用 mjlab 和同步多 GPU off-policy 训练，把 FB 的墙钟训练时间从约三天缩短到数小时，并在 EMD、Joint MAE 和目标到达上优于发布的 BFM-Zero。第二，作者提出 TeCH，用对比学习构造能表达时间可达性的潜空间，再用“下一状态离潜目标近了多少”作为稠密奖励。TeCH 的 actor 同时受 representation、style 和 sim-to-real auxiliary 三类 critic 约束。第三，UFO 把机器人结构和动作数据抽象成显式配置与 RobotState 接口，所以不同机器人只需提供正确的形态配置和专属重定向数据，就能复用主训练链路。第四，论文在 G1 实机上验证了遥操作、抗推和跌倒恢复。

我认为论文最有价值的地方不是某个单独数字，而是把无监督行为表示、训练基础设施、多机器人接口和实机系统连成了一条可复现链路。它的限制也很明确：后退和侧走仍不稳定，遥操作有延迟，LAFAN1 的行走和交互覆盖不足，而且 TeCH 不像 FB 那样直接支持统一奖励优化。

## 15. 高频提问与参考回答

### Q1：UFO 是一个算法还是一个框架？

是框架。UFO-FB 和 UFO-TeCH 是该框架的两个算法实例；TeCH 才是论文新提出的表示学习算法。

### Q2：为什么叫无监督，明明用了动作数据和奖励？

因为它不为每个下游任务提供人工标签或任务专属奖励。动作数据提供行为先验，算法使用内在表示奖励和辅助约束完成通用预训练。

### Q3：UFO 与动作跟踪 PPO 的本质区别是什么？

跟踪 PPO 直接优化“跟上某条参考轨迹”；UFO 先学习一个可复用潜行为空间，跟踪只是零样本下游任务之一，还可以做目标到达、奖励优化或遥操作。

### Q4：UFO-FB 为什么比 BFM-Zero 快？

主要来自 mjlab 吞吐、同步多 GPU、每卡独立环境和 replay buffer、梯度 all-reduce，以及更大的环境/buffer/batch 和重新调优的超参数，不是只改了一个网络层。

### Q5：off-policy 对这里有什么意义？

经验可放入 replay buffer 重复学习，提高样本利用率；同时多 GPU 可以并行探索更广状态空间。

### Q6：TeCH 学的“时间距离”是什么？

不是欧氏姿态距离，而是在环境动力学下，从一个状态到另一个状态需要多少步、是否容易到达的关系。

### Q7：为什么 TeCH 同时需要 `L_dist` 和 `L_step`？

前者区分时间上遥远的状态，建立全局可达结构；后者让相邻状态连续，避免潜空间抖动和断裂。

### Q8：TeCH 奖励为什么是稠密的？

每个转移都能计算到潜目标的距离减少量，不必等最终到达才得到信号。

### Q9：三个 latent 来源分别解决什么？

随机 latent 保证多样探索；在线 latent 保证目标可达；专家 latent 注入人体动作先验。

### Q10：三个 critic 分别是什么？

`Q_REP` 优化潜目标进度，`Q_D` 约束人体动作风格，`Q_R` 提供关节限位和 sim-to-real 辅助目标。

### Q11：TeCH 是否全面优于 FB？

不是。TeCH 目标到达和恢复更快，但精度可能略低、动作可能不够自然，而且不能直接提供 FB 式统一奖励优化接口。

### Q12：为什么 SONIC 终止前误差很低，完整轨迹却变差？

SONIC 是强跟踪器，但跌倒或严重偏离后恢复较弱。只统计终止前会排除失败后段；UFO 的完整轨迹指标体现了恢复能力。

### Q13：`update-z` 越小是否一定越好？

仿真跟踪误差通常更低，但动作压缩和柔和性下降，实机更易抖动或频繁调整。论文建议 10–100 折中。

### Q14：环境数是不是越多越好？

不是。更多环境提升探索，但论文观察到超过约 1024 env/GPU 后边际收益变小。

### Q15：为什么新技能不能直接合并数据后统一 prioritized sampling？

难动作会持续获得高优先级，训练被少数难样本支配并可能发散。UFO 先固定比例选数据集，再在数据集内部做优先采样。

### Q16：cartwheel 为什么用 0.95/0.05？

95% 保留原基础行为分布，5% 给新技能稳定曝光。它是论文实验中的有效设定，不意味着所有新技能都必须固定用这个比例。

### Q17：换机器人只换 XML 就行吗？

不行。还要明确 action/joint 顺序、body semantics、执行器限位和动力学、默认姿态、接触结构，以及与该机器人匹配的重定向动作数据。

### Q18：论文的多机器人“通用”是不是零样本跨机器人？

不是。它指复用训练和推理代码，通过机器人配置及机器人专属动作数据完成适配；仍需要对新机器人训练。

### Q19：实机遥操作的数据链路是什么？

VR 和脚 tracker 捕获人体 → GMR 重定向 → encoder 生成潜目标 → UFO policy → SDK2/CycloneDDS 控制。

### Q20：鲁棒性从哪里来？

作者认为主要来自无监督探索覆盖了更广的异常状态和转换，使潜行为空间更连续；跌倒和扰动状态不再完全是训练分布外。

### Q21：UFO 的最大局限是什么？

论文自己指出后退/侧走不稳、全局跟踪有限、遥操作延迟、LAFAN1 数据覆盖不足，以及完全无监督范式不能使用任务专属终止条件。

### Q22：当前 T800 迁移最容易出错的地方是什么？

关节/action 顺序、根姿态坐标系、四元数顺序、body semantics、执行器参数、物理限位，以及动作数据是否直接对应 T800。任何一项错位都可能使训练“能跑但动作错误”。

## 16. 容易说错的地方

- 不要说“UFO 就是 TeCH”；UFO 是框架。
- 不要说“UFO 完全不用动作数据”；它使用无标签动作示范。
- 不要说“TeCH 全面替代 FB”；两者能力边界不同。
- 不要把 3–4 小时演示策略、6 小时 H200 结果和 12–14 小时 4090 结果混为一谈。
- 不要说“环境越多越好”；论文明确观察到边际收益递减。
- 不要说“换 XML 就能换机器人”；还需要配置、语义、执行器和机器人专属动作数据。
- 不要把 UFO 预训练和我们之前的 tracking PPO 当作同一种训练。
